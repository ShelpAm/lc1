# 玩家身份与本地多人模拟

`PlayerId` 表示玩家身份，`CharacterId` 表示角色身份，两者是不同类型、不同编号空间。
存档中的角色 `keyid` 在运行查询边界转为 `CharacterId`，YAML 格式不变。
玩家到受控角色的绑定来自存档，保存格式见[存档](save-data.md#会话-sessionyaml)。
同一角色最多绑定一个玩家；世界可以没有玩家，也可以同时有多个玩家。

## 输入与绑定

宿主以已确定的玩家身份调用 `GameSimulation::connect(PlayerId)`，得到 `Connection`。
未知身份在绑定入口报错；之后只通过 `connection.submit(PlayerControls)` 提交操作，
输入消息不携带可更换的玩家 ID。句柄借用模拟，模拟必须比句柄长寿。
这是本地输入句柄，不是认证服务或网络连接，不提供独占登录语义。
绑定和角色名单在一个模拟实例内固定；当前不支持运行时注册、换角色、重连或角色生成。
释放控制时通过绑定句柄提交空输入；销毁句柄本身不改变持久玩家身份。

每个玩家分别维护待消费输入、输入序号和消费确认，tick 仍属于整个世界。
输入合并和一次性消费约定见[输入](input.md)及[固定步长模拟](code-layout.md#固定步长模拟与线程交换)。
`GameWorld` 拥有各玩家持续控制值和稳定地址的角色借用；角色控制器读取对应控制值。
每个 tick 先推进全部角色，再按玩家 ID 顺序处理交互，最后统一更新对话。
同一对象的竞争遵循该顺序及现有对话互斥规则，不新增锁或并发玩法执行。
对话按每个参与者的人工控制身份等待回答，NPC 请求门控也分别计算。
队伍可包含多个玩家；招募保留玩家控制器，跟随/等待命令只适用于 AI 成员。

## 快照与本地观察者

`WorldSnapshot::characters` 保存全部角色姿态、动作序号和台词。
`players` 按 `PlayerId` 保存受控角色编号、输入确认、背包、队员数、交互目标及可选回答。
这只是本地值交换的数据划分，不是网络广播协议，也不提供背包或对话的网络可见性策略。
表现插值只改变角色姿态，玩家数据和动作序号取最新已完成 tick。

`GameSession` 持有一个绑定句柄。`WorldPresentation` 和 HUD 显式使用这个本地观察者，
不能从共享世界里推断“唯一玩家”。涉及观察者的台词显示在 HUD，其余台词显示在头顶。
点头和挥砍都由模拟发布角色动作序号，各观察者据此播放动画。
相机、音频监听器、菜单、曝光和示例光照仍属于本地表现。

`ApplicationConfig::local_player` 选择本地玩家，默认 `PlayerId{1}`；启动可用
`LC1_PLAYER_ID` 指定另一条已有绑定。身份不存在时明确报错，不退回第一名玩家。
默认种子只包含一个玩家，可以在 `session.yaml` 增加绑定，或通过双玩家 CPU 测试验证。

## 宿主职责与验证边界

当前 `Application` 同时拥有本地宿主和客户端：会话只提交命名保存/读档请求，
由 Application 调用模拟 checkpoint、写盘或替换整个模拟。
绑定输入句柄不提供保存和读档操作。未来远程客户端不能直接复用宿主的世界管理入口。

CPU 测试覆盖双玩家独立输入与释放、独立确认、并行交互、人工回答、各自背包和存档往返，
以及没有玩家的世界。网络传输、身份认证、动态加入/离开、预测和回滚尚未实现。
