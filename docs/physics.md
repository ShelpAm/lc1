# 角色物理

当前物理范围是直立角色在静态高度场和轴对齐体块中的运动。
`CharacterMotion` 是实际执行求解的组件，由每个 `Character` 按值独占；代码位于
`include/lc1/game/physics/character-motion.hpp` 与 `src/game/physics/character-motion.cpp`。
角色意图、操作和玩法规则见[角色文档](character.md)，世界更新顺序见[代码边界](code-layout.md#每帧时序)。

## 所有权与输入

`Character` 决定移动速度、朝向和动作请求，将水平期望速度交给物理组件。
组件不依赖 `Character` 类、`CharacterIntent`、控制器、相机或渲染；`CharacterBody` 是共享的身体参数值类型。
组件拥有接地标记、竖直速度和待执行跳跃请求，不拥有世界变换、不长期借用位置。
构造、`update()` 和 `move()` 只在调用期间通过引用更新角色脚底位置，因此移动物理组件不会留下失效的位置指针。
角色对象本身为维持注册表、队伍和对话借用的稳定性禁止移动，见[角色身份](character.md#身份与队伍关系)。
`WorldCollision` 提供静态碰撞查询，借用 `Continent` 的只读几何；组件不复制大陆几何。
`Continent` 保留地理、体块、地形高度采样与缓存的区域通行属性。
脚下支撑面、头顶底面、身体净空、水平扫掠和沿墙滑动全部在
`game/physics/world-collision.*` 实现，`Continent` 不保留这些接口的转发方法。
地图构造验证道路和入口时也调用同一碰撞模块，避免校验与运行期各维护一套碰撞规则。

`WorldCollision` 是轻量只读视图，构造不复制数据、不重建索引；查询仍按扫掠范围访问地形格。
它借用的大陆在视图使用期间必须存活且地址不变。角色每次调用创建短期视图，
不把指向大陆或角色的视图保存到 `CharacterMotion` 中；大陆被替换或移动后需重新创建视图。

角色构造验证身体与出生位置，再由组件尝试贴合附近可站立支撑面；空中出生保留为下落状态。
当前角色间没有相互碰撞，也没有通用刚体、质量、摩擦或冲量模拟。

## 配置与时间

`CharacterMotionSettings` 集中定义重力加速度、跳跃高度和运动计算的最大步长。
默认值在组件头文件中；构造 `Character` 时可在 `CharacterBody` 后传入该配置，按值保存，存档暂不记录它。
重力必须有限且大于零，跳跃高度必须有限且非负，最大步长必须有限、为正且可表示为非零 float。
角色身体参数仍在 `CharacterBody` 中；不另外保存一份碰撞尺寸。

模拟时间必须有限且非负，没有 0.1 秒截断，也没有最大计算次数后丢弃时间的逻辑。
每次更新按配置的最大步长细分，默认 1/60 秒，最后不足一步的时间立即推进。
这是可变步长细分，没有跨帧累积器；长帧计算量随模拟时间增加。
时间大到减去一步已无法表示进展时明确报错，避免无进展的死循环。
玩家／AI 每帧生成一次意图，同一水平期望速度用于各运动步；跳跃请求只消费一次，零时间不消费。
控制器、对话与表现仍每帧更新一次；长帧不等价于多次重新决策的世界更新。

## 碰撞与重力

每步先执行水平扫掠和沿墙滑动；着地时可以抬高身体重试，以跨上允许高度的台阶。
抬高路径检查头顶空间，最终支撑位置也必须能容纳完整身体。
随后检查接地；仍在空中时，用恒定重力的位移公式计算竖直运动。
水平运动与竖直运动仍分开求解，目前不是任意方向的统一三维扫掠。

向上运动通过 `WorldCollision::ceiling_above()` 查询头部足迹扫过的最低实体底面。
装饰性非实体体块不参与；身体部分位于屋檐下也会碰撞。击中后将脚底限制在底面减去身高处，
清除上升速度，并继续模拟本步剩余时间的下落。
一步跨过跳跃最高点时，在最高点拆开上升和下降，以最高点为下降支撑查询的起点。
下降扫过整个竖直距离，落到高度场或标记为可站立的体块顶面，避免高速下落越过支撑面。

地形支撑、体块顶面与可站立标记继续遵循[大陆设计](continent.md)及[世界地图](world-map.md)。
目前没有移动平台、坡面滑落或任意三角网格碰撞。后续加入箱子、投射物等共享模拟对象时，
再根据真实交互需求引入世界级物理调度与碰撞数据所有权；当前不增加空的 `PhysicsSystem` 管理层。

## 验证

`character` CPU 测试覆盖不同帧率的跳跃、长帧移动与落地、跨平台、薄天花板与屋檐边缘、
撞顶后继续下落、跨最高点的轨迹、配置校验以及移动物理组件后的运动状态。
`continent`、`world_map`、`game_world` 与 `player_view` 测试继续验证世界空间和更新链路。
这些检查不替代 GPU 验证或窗口操作检查。
