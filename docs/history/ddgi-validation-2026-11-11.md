# DDGI 首版验证（2026-11-11）

代码为 `codex/ddgi` 工作区，基于 `16f81d7` 的未提交改动。现行契约见
[光照](../lighting.md#ddgi-漫反射间接光)、[渲染图](../render-graph.md)。

## 环境与方法

Linux x86_64 / Release，Clang 23，本地 Conan 缓存及 Slang；实际渲染设备为
NVIDIA GeForce RTX 4060 Laptop GPU。GPU 测试显式启用本地 Conan 提供的
Khronos 验证层与同步验证，没有使用 `LC1_NO_VALIDATION`。
Release 主游戏按原有规则不启用验证层，其运行记录不能替代 GPU 测试的验证结果。

独立 worktree 单独生成 Conan/CMake 构建树，复用原工作区的只读 VMA-Hpp 源码与本地美术资源，
没有复制原构建缓存或把源码写回原工作区。临时资产链接位于忽略的 `runtime/assets/` 内。

## 已检查范围

- Linux Release 主程序及 GPU 目标编译，CPU CTest 24/24 通过。
- `lc1_pbr_tests`：均匀天空的独立 Lambert 能量参考、RGB、双帧槽历史、体积滚动、
  关闭/重新开启、无灯无天空为黑、屏幕外纹理自发光反弹、屏幕外受光墙面的漫反射反弹，
  以及不改变可见接收面时加入遮挡物后的时间收敛。GI 命中覆盖 uint16 与 uint32 索引。
- 原 PBR 材质、纹理、法线图、HDR、tone mapping、MSAA、resize、模型动画与材质生命周期回归。
- `lc1_shadow_path_tests`：空帧、投影资格、双帧槽、resize 与真实遮挡回归。
- 首版主场景曾实窗检查。用户反馈偏暗后，白天天空从 `(0.025, 0.035, 0.055)` 提高为
  `(0.08, 0.105, 0.14)`，仍乘太阳高度；体积水平覆盖从 28 米扩大为 60 米，主游戏初始曝光改为 2。
  更新后主程序运行正常，但最终截图时桌面已锁定，最新提亮版的实窗观感尚待用户验收。

## 性能观测

固定展示区、800×600、4×MSAA、曝光 1，使用 Vulkan GPU timestamps 包围完整 Renderer 录制，
不计输出图片的读回与 CPU 资产加载。稳定帧取连续 8 帧平均。一次优化后的观测为：

| 设置 | GPU 渲染耗时 |
|---|---:|
| DDGI 关闭 | 3.08 ms |
| DDGI 开启，稳定更新 | 3.86 ms |

该次差值约 0.78 ms；最终复测为 3.43 → 3.91 ms，差值约 0.49 ms。
这些数值不能外推到全分辨率、其他场景、GPU 或驱动。
初始化需要更新全部 2048 个探针，稳定帧只更新 128 个；初始化结果单独由测试打印。
射线方向改为 CPU 每帧只生成一次、通过 UBO 共享之前，同配置曾观察到约 3.6 ms 的额外开销。
这些是短样本调优数据，没有温度/频率锁定或统计置信区间，不构成性能保证。

测试输出在构建目录 `artifacts/`：`ddgi-disabled.ppm`、`ddgi-enabled.ppm`、
`ddgi-daylight.ppm`（曝光 2）、`ddgi-zero-sky.ppm`。零天空对照仍保留显式灯光，不能解释为全黑夜景。

## 未验证与限制

Windows、Debug、远程 CI 未验证。薄墙/小房间漏光、移动遮挡的延迟、100× 昼夜下的跟随速度、
大幅移动时新区域填充和多场景帧时间仍需实际验收。
当前是单次漫反射 GI，没有探针重定位、多级体积、镜面间接光或天空背景同步。

## 静态 LED 闪烁与近场缺光回归

用户截图来自本工作树的 DDGI 版本。另一份无 DDGI 工作树上的“仅自发光材质”修改
不能验证此问题，已撤回；本次不关闭 LED 对周围表面的照明。

固定相机和 1×1 米发光面，零天空、零显式灯光，连续 512 帧、后 256 帧统计：
原球面随机命中路径的红通道最低 0.00247383、最高 0.0140915、平均 0.00765181。
仅把远场改为显式三角形积分后，1 米与 2 米接收面仍为零，5 米反而为 0.00940704，
证明仅修时间噪声不能解决小于一格探针间距的近场缺光。

最终采用发光三角形预处理、固定四点立体角积分、遮挡查询及 4～8 米平滑近远分区。
相同静态测试最低、最高均为 0.0106354。1、2、3、5 米的接收值分别为
0.241699、0.0737915、0.0341797、0.0106354；另测 3.9/4.1/7.9/8.1 米过渡点。
参考能量由 CPU 64×64 面积积分独立计算；远场允许 30% 探针插值误差，过渡相邻点不允许
超过 10% 的反向跳变。7.9→8.1 米存在约 4% 的插值增量，并非解析面积光的严格单调解。

纯 LED 展区（无天空、无显式灯光）的连续 32 帧最大 HDR 通道差为 0.00195312，
回归上限 0.005。另检查镜像发光面的朝向、近场 LED 关闭后不保留冻结亮度、真实遮挡，
以及原天空/滚动/多级覆盖/双帧槽/材质与 MSAA 检查。

Linux Release 主程序与 `lc1_pbr_tests`、`lc1_shadow_path_tests` 编译并通过，
CPU CTest 24/24 通过。两个 GPU 目标均在 RTX 4060 Laptop GPU 上开启 Khronos 验证层运行，
没有 validation 或同步验证报错。查看了 `artifacts/ddgi-led-only.ppm` 与
`artifacts/ddgi-led-near.ppm`：LED 紧邻的平台和背板有受光，不再只有远处零散亮斑。
这些是实际 GPU 渲染读回图，交互窗口的用户验收仍单独进行；Windows/Debug/远程 CI 未测。

初版逐屏幕采样重复读取网格时，800×600 场景曾达到约 126 ms，不能交付为性能改善。
每帧一次的三角形世界坐标/纹理预处理后，两次同配置观测为直接光 23.95 ms / 总计 27.70 ms，
以及直接光 16.96 ms / 总计 30.43 ms；初始化分别约 232 ms 与 88 ms。
未固定频率/温度，不能把这些波动样本当成稳定预算；显式发光积分确实增加 GPU 成本，
成本随发光三角形数和屏幕尺寸增加。稳定批次射线附件已缩至实际更新高度，
首次初始化仍需要完整高度。

### 近场范围剔除

预处理在空闲的 RGBA 通道中保存原三角形的包围球；近场按原三角形分组，
先拒绝完全超出 8 米或位于接收面背后的组，再计算四个子样本。
未减少相关样本、改变曝光或以随机漏采恢复性能。
`lc1_pbr_tests` 再次通过，验证输出干净，LED 亮度统计和整场景最大帧差保持上述结果。
800×600 一次测量为直接光 12.8619 ms、开启后 24.0965 ms，初始化 97.1259 ms。
测试间基础帧时间变化明显，不据此声称固定提速比例；约 11.2 ms 的额外成本仍需进一步优化。

### 学习 Lumen 后的共享候选与跨帧缓存

参考 Epic 的 [Lumen 技术文章](https://www.unrealengine.com/tech-blog/unreal-engine-5-goes-all-in-on-dynamic-global-illumination-with-lumen)
中关于共享采样工作、空间缓存和跨帧复用的设计。当前实现缓存发光候选，不等同于 Lumen
的辐亮度缓存、Surface Cache 或重要性采样，也没有宣称复刻 Lumen。

先尝试每帧构建屏幕候选，再将最终方案改为可复用的四级世界空间候选位掩码。
各帧槽只在覆盖原点或发光网格/变换/列表变化时重建；缓存不按亮度筛选，也不缓存遮挡。
因此材质亮度和动态遮挡仍使用当帧数据。远场融合另跳过零能量样本的法线解码。
描述符容量从 DDGI 图片槽位数量推导，补齐新增资源所需空间；第一次完整回归暴露的
image heap full 已修复，最终完整 GPU 回归通过。

增加独立全遍历 fragment 入口与 GPU differential/timestamp 测试：同一帧数据、同一提交中，
交替反转顺序运行完整遍历与缓存查询各八次，比较所有 RGB 像素。400×300 半分辨率查询的
最终观测为完整遍历 1.92932 ms、缓存 1.53254 ms，约减少 20.6%，最大 RGB 误差为零。
这衡量查询通道，不包含缓存重建，也不能当作整帧提速；稳定静态帧不重建候选缓存。
源移动/近远距离切换、镜像、开关、滚动、双帧槽和新增遮挡仍通过原有 GPU 检查。

最终 800×600 场景一次观测为直接光 10.2668 ms、DDGI 开启 19.7279 ms、初始化 51.8334 ms；
未锁定 GPU 频率，不和不同次运行的帧时间直接计算整体提速比例。
完整静态 LED 展区最大帧差仍为 0.00218201，小 LED 最低/最高均为 0.0106354。
Linux Release 主程序编译、CPU CTest 24/24、PBR 与 shadow path GPU 测试通过，验证输出干净。
Windows、Debug、远程 CI 未验证。剩余发光积分仍有开销，固定预算重要性采样及辐亮度复用
尚未实现，不能据这次候选缓存优化宣称性能问题完全解决。

## 优先太阳照明，默认暂停自发光积分

主场景沿用默认 `DiffuseGi::emissive_lighting = false`：材质仍显示自身发光，但不枚举发光三角形，
探针不追加发光样本，近场查询直接返回零。太阳、其他显式灯光和天空的漫反射照明继续使用原路径。
自发光专项测试显式启用该选项，保留既有实验覆盖。

Linux Release 主程序与 PBR 测试构建通过，CPU CTest 24/24 通过。RTX 4060 Laptop GPU 完整 PBR
及 `--showcase` 复测通过，启用 Khronos 验证层，无 validation/sync 报错。
新增默认不接收屏幕外自发光的断言，太阳离屏墙面颜色反弹在不启用自发光积分的情况下通过。
800×600、4×MSAA 展区复测：直接光 5.92978 ms，DDGI 稳定帧 6.6254 ms，初始化 6.83731 ms，
该次额外成本约 0.70 ms。首次运行曾得到直接光 26.8565 ms、DDGI 8.56274 ms，表明运行状态波动明显，
不据此报告固定提速倍数。未进行交互实窗或 Windows 验收。
