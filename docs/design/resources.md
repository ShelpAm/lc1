# 资源

## 当前铁盔打造契约

`resources/recipe.hpp` 的 `Recipe` 拥有输入与输出 `RecipeStack` 列表，借用只读资源定义；
`can_craft` / `craft` 负责检查与执行。铁盔配方位于 `resources/crafting.hpp`：
生铁 1、木材 1、Moneta 5 → 铁盔 1。该配方使用进程期只读定义，不依赖铁匠背包中的零数量占位。

`Bag` 的条目是 `ResourceStack { keyid, quantity }`，只通过 `add`、`remove`、`quantity_of` 操作，
`quantities()` 给出只读的编号到数量视图；`add` 和 `remove` 接收只读资源引用，但只在该次调用内使用，
条目本身不保存定义，所以背包不附带寿命要求，同一编号的定义必须一致。
构造时指定重量上限，单位克；角色默认 20000 克（20 kg），每单位资源使用目录中的克重。移除数量为零时直接成功且不改变背包，无需已有对应堆叠；移除到零时删除堆叠。
打造在候选背包中先扣材料再添加产出，成功后同时提交数量与容量计数。
材料不足、产出超容量、数量溢出或分配失败均不改变原背包；满包在扣料腾出空间后仍可打造。
背包容量和资源编号、数量通过 [checkpoint](../save-data.md) 保存恢复，资源定义仍来自目录。
编号到定义的解析统一走 `resources/catalog.hpp` 的 `find_resource(keyid)`；世界不再另存资源注册表。
打造产物可按下文穿戴规则装入槽位；资源产出与经济段落仍为玩法设计。

## 资源系统

资源系统分为以下几个模块：
- 资源产出：资源出现方式
- 资源流通（交易等）
- 资源消耗：资源完全消失的方式

模板
```
- 产出：暂无
- 流通：暂无
- 消耗：暂无
```

资源分为以下几个类型：

### 莫那塔（货币）
基本的交易媒介，主要用于购买物品、服务等。

- 产出：暂无
- 流通：探索，完成任务的奖励，交易，购买/出售 物品、服务
- 消耗：暂无

- 包装：称作 moneta，莫那塔。

  > Moneta 源自拉丁语 *monēta*，意为“货币、铸币”，也是英语 money 与 monetary 的词源之一。

### 木材 (Wood)
用于装备铸造及其他。

- 产出：砍伐树木
- 流通：野外探索，任务奖励，交易
- 消耗：烧炼

### 生铁 (PigIron)
用于装备铸造及其他。

- 产出：开采矿物，熔炼物品
- 流通：野外探索，任务奖励，交易
- 消耗：打造装备

## 物品、装备与武器的定义

`Resource` 只保存通用编号、名称、分类与克重，不依赖装备或武器类型。
`equipments.yaml` 与 `weapons.yaml` 分别提供防具属性和手持物品属性，记录的 `keyid`
就是同一个资源编号，不再使用独立编号空间。例如 Resource 4 是铁头盔，Equipment 4 提供 Head 与护甲；
手电筒是 Resource 1005，Weapon 1005 提供使用行为和模型。
所有附加定义必须能解析到 Resource，同一资源不能同时有防具和武器定义；在存档入口一次校验。

Equipment 与 Weapon 是可共享的只读定义，不是单件物品实例。世界拥有定义，角色借用；
背包仍只保存资源编号与数量。没有耐久、词缀或绑定差异时，不额外创建 ItemId。

防具按 Head、Body、Foot 放入槽位，角色只有一个 `Weapon* main_hand`，没有武器槽位 map。
`Weapon` 是具有虚析构和 `use(Character&) const` 的抽象基类，
`MeleeWeapon`、`RangedWeapon`、`Flashlight`、`Torch` 分别实现使用行为。角色只调用当前主手的 `use()`；
近战派生类请求角色开始攻击，手电筒请求切换开关，冷却、攻击进度和灯光状态仍归角色所有。
`WeaponAction` 只用于存档类型判别和表现元数据，世界装配时一次创建对应派生类，不参与角色的使用行为分派。
快照只复制无行为的 `WeaponDefinition` 数据，不复制或跨线程借用多态行为对象。
`WeaponKind` 从定义类型推导为近战、远程、工具，不额外保存可变分类；工具暂无共同实现，不建立空的 Tool 中间类。
当前近战命中已实现；远程类别保留，但没有新增弹道或射击玩法。工具先实现手电筒，后续按具体需求增加使用行为。

## 穿戴与卸下

UI 从快照读附加定义并发送 `EquipmentRequest`，GameSession 经 Connection 提交到模拟线程。
GameWorld 校验资源、目标和控制关系：玩家可管理自己，以及自己担任队长的小队中的非玩家普通成员。
角色规则从目标角色自己的背包扣一件，将旧装备退回同一背包，然后更新槽位。
数量不足、容量不足或死亡时拒绝，背包与槽位都不改变；请求只消费一次。

重量上限仍表示背包容量，穿戴中的物品不计入背包；卸下和换装需容得下退回物品。
UI 对无空间的卸下按钮显示原因。转移、丢弃和预设尚未实现。
铁头盔（资源 4）使用硬编码的圆顶与帽檐网格，穿戴时显示、卸下时隐藏；
表现层共享 GPU 几何，各角色独立跟随 `Head` 节点动画（无该节点时按身体高度定位）。
其他防具暂未挂载外观。
存档保存背包数量与已装备资源编号，迁移细节见 [存档](../save-data.md)。

## 手电筒

手电筒占用唯一主手槽，初始关闭，左键按下切换一次开关，不挥砍、不造成伤害。
换装、卸下或死亡后不发光；开关状态随 checkpoint 保存，攻击进度不保存。
`builtin:flashlight` 由 CPU 代码生成筒身与镜片，无外部模型依赖。
WorldPresentation 为每个角色生成对应模型与聚光灯，只在该角色装备手电筒且开灯时启用，
从手中模型的镜片位置发光，方向随角色观察方向（含俯仰），不固定绑定本地观察者。
新种子场景的初始背包包含一支手电筒，旧 checkpoint 不补发物资。

此前的可选属性块、堆叠上限及总负重提案已被当前方案替代，原文保存在
[历史提案](../history/items-optional-equipment-proposal-2026-11-10.md)。

## 火把

火把是 Resource / Weapon 1006，占用唯一主手槽，装备即燃烧；左键不挥砍或切换开关。
卸下、换装或死亡时火焰与照明关闭。不消耗燃料，不增加持久开关状态；checkpoint 保存已装备的资源编号。
新种子场景初始背包提供一支，旧 checkpoint 不补发。`builtin:torch` 生成木柄与燃烧头，
火焰和照明实现见 [光照](../lighting.md#火把)。
